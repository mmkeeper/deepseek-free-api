# Hermes Plugin: deepseek-session TTS

TTS-провайдер для Hermes Agent, озвучивающий ответы через локальный
DeepSeek-прокси (`POST /v1/audio/tts`).

Провайдер **не синтезирует присланный текст**. Он находит по тексту сессию
Hermes и номер ответа ассистента, отправляет список сообщений этой сессии в
прокси, а прокси восстанавливает сессию и озвучивает ответ с нужным номером.

---

## 1. Что в комплекте

| Путь | Что это |
|---|---|

| `AGENTS.md` | **инструкция для AI-агента**: как поставить и настроить |
| `docs/ARCHITECTURE.md` | как работает поиск и почему именно так |

| `tests/test_plugin.py` | автотесты логики (без сети и без Hermes) |
| `skills/local-llm-proxy/` | скилл Hermes: работа с прокси и его границы |

---

## 2. Требования

* Hermes Agent с поддержкой плагинов и TTS-провайдеров.
* Локальный прокси, слушающий `http://127.0.0.1:18632`, с эндпоинтом
  `POST /v1/audio/tts`.
* `ffmpeg` в `PATH` — нужен только если контейнер ответа не совпадает с
  расширением целевого файла (обычно не нужен: прокси отдаёт Ogg Opus).
* Python 3.9+.

---

## 3. Установка (кратко)

```bash
# 1) скопировать плагин в профиль Hermes
PROFILE=~/.local/share/hermes/profiles/<ПРОФИЛЬ>      # Linux
# Windows: C:\Users\<user>\AppData\Local\hermes\profiles\<ПРОФИЛЬ>

mkdir -p "$PROFILE/plugins/deepseek-session-tts"
cp deepseek-session-tts/__init__.py "$PROFILE/plugins/deepseek-session-tts/"
cp deepseek-session-tts/plugin.yaml "$PROFILE/plugins/deepseek-session-tts/"

# 2) скилл (по желанию, но полезно)
mkdir -p "$PROFILE/skills/local-llm-proxy/references"
cp -r skills/local-llm-proxy/* "$PROFILE/skills/local-llm-proxy/"

# 3) ОБЯЗАТЕЛЬНАЯ настройка — иначе ответ озвучится несколько раз
hermes config set tts.deepseek-session.max_text_length 1000000

# 4) перезапустить Hermes
```

Полная пошаговая инструкция с проверками — `AGENTS.md`.

---

## 4. Почему `max_text_length` обязателен

Hermes режет текст на чанки по `tts.<provider>.max_text_length`, а для
незнакомого провайдера берёт `FALLBACK_MAX_TEXT_LENGTH = 4000`. Плагин текст
игнорирует: каждый вызов возвращает один и тот же ответ сессии. Значит
N чанков = N запросов = **один ответ, озвученный N раз подряд**.

Симптом в `agent.log`:

```
TTS text for provider ... split into 2 chunks
```

и два файла `.chunk001.ogg` / `.chunk002.ogg` одинакового размера.

CLI при установке предупредит `not a recognized config key` — это нормально,
ключ читается динамически. После правки нужен перезапуск: `load_config`
кэшируется.

## 5. Конфигурация

Секция `tts.deepseek-session` в `config.yaml` **профиля Hermes** (пример — `config.example.yaml` в этом каталоге). Все ключи необязательны.

```yaml
tts:
  deepseek-session:
    base_url: http://127.0.0.1:18632   # адрес прокси
    voice: mira                        # mira | echo | stella | tide
    timeout: 300                       # HTTP-таймаут одного запроса, с
    max_text_length: 1000000           # ОБЯЗАТЕЛЬНО, см. §4
    message_index: 12                  # override: озвучить конкретный номер
    pending_wait: 45                   # сколько ждать генерации ответа, с
    pending_poll: 0.7                  # пауза между повторами, с
```

`message_index` — **отладочный override**. Если задан, поиск по тексту не
выполняется: плагин берёт самую свежую известную сессию и просит прокси
озвучить ответ с этим номером. Для обычной работы ключ должен отсутствовать.

---

## 6. Использование

1. Включить озвучку: `/voice tts`.
2. Ответы ассистента начинают озвучиваться автоматически.
3. Кнопка у сообщения озвучивает конкретный ответ.

Проверить, что провайдер виден:

```
hermes tts providers
```

## 7. Голоса

| id | пол | F0 (замер) |
|---|---|---|
| `mira` | женский | ~235 Гц |
| `stella` | женский | женский |
| `echo` | мужской | ~127 Гц |
| `tide` | мужской | ~94 Гц |

Голос передаётся в прокси как есть. Прокси не проверяет язык голоса:
неверная пара «голос + язык текста» вернёт `voice_unsupported_language`.

## 8. Известные ограничения

Полный разбор — `docs/ARCHITECTURE.md` и `docs/TROUBLESHOOTING.md`.

| Ограничение | Суть |
|---|---|
| Кросс-сессионный дефект | при переключении сессий может озвучиться последнее сообщение **уходящей** сессии; чинится только в ядре Hermes |
| Склейка ответов | при переключении desktop может отправить несколько ответов встык без разделителя — такой текст не находится ни в одном снапшоте |
| `text_to_speech` внутри хода | аргумент `text` не является ответом ассистента, искать его негде → ошибка |
| `/voice tts` не работает | провайдер не попадает в реестр стримеров; Hermes режет ответ по предложениям, фрагмент никогда не равен целому сообщению |

Поведение при неудаче — **тишина и ошибка в лог**, а не озвучка чужого
сообщения. Это осознанный выбор: прочитать не тот ответ хуже, чем промолчать.


`agent.tts_provider`, а проверяется чистая логика — санитайзер, стабилизация
нормализатора, поиск номера сообщения, кросс-сессионный сценарий.
