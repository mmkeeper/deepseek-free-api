# Разбор ошибок: deepseek-session TTS

Документ для случая «озвучка не работает». Идти сверху вниз: сначала найти
свою строку в логе, затем применить лечение.

Каталог логов: `$PROFILE/logs/agent.log`, `errors.log`, `gui.log`.
Файл диагностики: `$TMPDIR/deepseek_tts_debug.json`.

---

## 1. Быстрый сбор фактов

```bash
PROFILE=<путь к профилю>

# что вообще происходило с TTS за последнее время
grep -E "Generating speech|deepseek-session:|TTS audio saved|TTS generation failed" \
     "$PROFILE/logs/agent.log" | tail -40

# тела запросов, на которых прокси ответил ошибкой
cat "$TMPDIR/deepseek_tts_debug.json" | head -50
```

Ориентир — **пара строк** на каждый запрос:

```
Generating speech with plugin TTS provider 'deepseek-session'...
<одна из:>
  deepseek-session: сессия <id>, message_index=N, assistant: в списке X, в истории Y
  deepseek-session: ПРОМАХ. запрошено='...' (len N). Хвосты сессии ...
```

Есть только первая строка без второй — плагин упал между ними (смотри
`errors.log`). Нет вообще ни одной — запрос не приходил.

---

## 2. `TTS text ... split into N chunks`

**Причина:** не задан `max_text_length`.

Hermes режет текст на чанки по `tts.<provider>.max_text_length`, для
незнакомого провайдера берёт `FALLBACK_MAX_TEXT_LENGTH = 4000`. Плагин текст
игнорирует, поэтому каждый чанк даёт один и тот же ответ.

**Признак:** два файла `.chunk001.ogg` и `.chunk002.ogg` **одинакового**
размера.

**Лечение:**

```bash
hermes config set tts.deepseek-session.max_text_length 1000000
# перезапустить Hermes (load_config кэшируется)
```

Предупреждение `not a recognized config key` — нормально.

## 3. `озвучиваемое сообщение не найдено ни в одной сессии`

```
deepseek-session: текст не найден ни в одной из N известных сессий [...] —
озвучка отменена, чтобы не прочитать чужой ответ
deepseek-session: озвучиваемое сообщение не найдено ни в одной сессии —
текст не совпал ни с одним ответом ассистента
```

Это **самая частая** ошибка и почти всегда НЕ баг плагина. Смотреть на
строку `ПРОМАХ` выше: там указаны `len` и первые 90 символов запрошенного
текста.

### 3.1 `len` 7–8 тыс. против обычных 0.5–2 тыс.

**Склейка ответов.** Desktop при переключении сессий отправил несколько
ответов встык **без разделителя**.

Признак: первые 90 символов совпадают с началом одного из ответов, но не с
целым; в базе видно, что это конец одного сообщения + начало другого.

```
запрошено = 'Смотрю эту сессию — и в логах, и в базе.Ключевое расхождение: ...'
                    ^ конец msg#11521        ^ начало msg#11523
```

**Лечение:** нет, вне плагина. Это кросс-сессионный дефект ядра (§4).
Поиск по вхождению/хвосту ослабил бы защиту «не прочитать чужое» —
сознательно не делаем.

### 3.2 Расхождение одного знака препинания

```
запрошено:  'закончится. Сейчас'   (761)
в снапшоте: 'закончится, Сейчас'   (1071)
```

**Причина:** desktop применил свой `sanitizeTextForSpeech` (`\n\n` без знака
→ точка), а плагин сравнивал с сырым markdown (там `\n\n` → запятая).

Это уже **исправлено** портом санитайзера. Если снова видно — проверь, что
установлена свежая версия `__init__.py` (должны быть функции
`_sanitize_for_speech`, `_strip_md_tables`, `_md_row`).

```bash
grep -c "_sanitize_for_speech" "$PROFILE/plugins/deepseek-session-tts/__init__.py"
# ожидается >= 2
```

### 3.3 Многоточия

```
skillview(name='..')  ->  skillview(name='.')
```

**Причина:** нормализатор Hermes неидемпотентен. **Исправлено** стабилизацией
до неподвижной точки. Если видно снова — версия плагина старая.

### 3.4 Хвосты сессий в логе не содержат искомого текста вообще

Смотреть на список сессий в строке «не найден ни в одной из N»:

* сессия, из которой пришёл запрос, **отсутствует** в списке → снапшот не
  захватился: middleware `llm_request` не срабатывал для неё. Отправь
  сообщение, чтобы прошёл ход.
* сессия есть, но текст не в её хвостах → скорее всего §3.1 (склейка).

### 3.5 Текст есть, но «не является последним ответом»

```
deepseek-session: реплика найдена в истории сессии <id>, но не является
последним ответом (assistant: N в списке, M в истории) — прокси её не знает
```

**Причина:** сообщение выпало из отправляемой истории при компрессии
контекста, либо это середина переписки. Прокси считает сессию по
отправленному списку — изменившийся список даёт другой ключ.

**Лечение:** нет. Озвучить нельзя: прокси не знает этого сообщения.

## 4. Ошибка в UI есть, а в логе ничего

**Это не потеря запроса.** Его не отправляли.

Проверка:

```bash
# 1. время записи сообщения
sqlite3 "$PROFILE/state.db" \
  "SELECT id, role, length(content), datetime(timestamp,'unixepoch','localtime') \
   FROM messages ORDER BY id DESC LIMIT 10;"

# 2. концы ходов и перезапуски процесса
grep -E "Turn ended|Loaded environment variables|в памяти новая сессия" \
     "$PROFILE/logs/agent.log" | tail -20
```

Если между записью сообщения и перезапуском процесса нет ни одной строки
`Generating speech` — запрос не приходил.

**Что это тогда:** кросс-сессионный дефект (§5). Озвучивалось последнее
сообщение **уходящей** сессии, а ошибка отобразилась у сообщения в новой.

---

## 5. Кросс-сессионный дефект

**Симптом:** при переключении между сессиями воспроизводится последнее
сообщение **предыдущей** сессии; ошибка может висеть у сообщения в новой.

**Причина (в ядре Hermes):** `use-auto-speak-replies.ts` перезаряжается
раньше, чем `$messages` заменяется на новую сессию
(`use-session-state-cache.ts`, замена через RAF). `stopVoicePlayback()`
при этом не вызывается.

**Лечение:** нет, без правок ядра. Решение владельца — «оставляем как есть».

## 6. Ошибки прокси

Строка вида `deepseek-session: прокси ответил <код>: <тело>`.

| Код | Тело | Значение | Действие |
|---|---|---|---|
| 400 | `message_not_voiceable` | сообщение не из истории прокси | проверь, что сессия та; обычно следствие §5 |
| 400 | `invalid_message_index` | номер вне диапазона | проверь `message_index` в конфиге |
| 400 | `not_assistant_message` | номер указывает не на ответ | то же |
| 400 | `message_pending` (редко) | ответ ещё пишется | плагин ждёт сам до `pending_wait` |
| 502 | `no_content` | последнее сообщение — только `t00l_calls` с пустым `content` | озвучивать нечего, это не текст |
| 502 | `voice_unsupported_language` | голос не подходит языку | смени `voice` |
| 502 | `voice_unsupported_language` / `invalid_voice` | голос не проверяет язык | смени голос на подходящий |
| 503 | `message_pending` | генерация ещё идёт | **штатно**, плагин повторяет до 45 с |

Тело последнего неудачного запроса целиком — в `$TMPDIR/deepseek_tts_debug.json`
(ключи `time`, `status`, `detail`, `payload`).

### 6.1 `прокси недоступен`

```
deepseek-session: прокси недоступен: <urlopen error ...>
```

Прокси не слушает порт.

```bash
curl -s http://127.0.0.1:18632/health
```

Нет ответа — прокси не запущен. Не поднимай его сам, сообщи пользователю.

### 6.2 `список сообщений ещё не захвачен`

```
deepseek-session: список сообщений ещё не захвачен (llm_request не срабатывал)
```

Поднимается только при `message_index` из конфига. Значит, ни одного хода
ещё не было. Отправь сообщение либо убери `message_index` из конфига.

## 7. `text_to_speech` внутри хода

**Симптом:** озвучка падает, когда ассистент вызывает инструмент
`text_to_speech`.

**Причина:** аргумент `text` — произвольный текст, а **не ответ
ассистента**. Искать его в истории негде.

**Лечение:** нет. Это отдельный сценарий: инструмент просит озвучить текст,
а бэкенд умеет озвучивать только свои ответы. Варианты — заглушить ошибку
или вернуть fallback на активную сессию; решение за владельцем.

---

## 8. `/voice tts` молчит

Потоковая озвучка для этого провайдера не работает by design:
`tts_t00l_speaker` режет ответ по предложениям, а фрагмент никогда не равен
целому сообщению. Плагины в реестр стримеров
(`tts_streaming._REGISTRY`) не попадают.

Работает: озвучка по кнопке у сообщения и автоозвучка целых ответов.

---

## 9. Диагностический чек-лист

Пройти по порядку:

1. `hermes tts providers` — есть ли `deepseek-session`.
2. `curl -s http://127.0.0.1:18632/health` — жив ли прокси.
3. `hermes config get tts.deepseek-session.max_text_length` — задан ли.
4. `grep "deepseek-session" agent.log | tail` — загружался ли плагин.
5. `grep "Generating speech" agent.log | tail` — приходят ли запросы.
6. Есть ли рядом строка `сессия ... message_index=...` или `ПРОМАХ`.
7. `ls -la $PROFILE/cache/audio/` — пишутся ли файлы, растут ли размеры.
8. Файл `.ogg` должен начинаться с `OggS`:
   ```bash
   head -c 4 <файл>.ogg | xxd
   ```

Если 5 молчит, а 6 в UI показывает ошибку — это §4.
