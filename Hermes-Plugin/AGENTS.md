# AGENTS.md — установка и настройка плагина deepseek-session TTS

Инструкция для AI-агента, которому поручено поставить этот плагин в Hermes
Agent и довести до работающей озвучки. Читать целиком перед действиями.

---

## 0. Что ты ставишь

Плагин TTS-провайдера `deepseek-session`. Он озвучивает **ответы ассистента
из истории сессии Hermes** через локальный DeepSeek-прокси.

Ключевое, что определяет ВСЁ поведение: провайдер **не синтезирует
произвольный текст**. Эндпоинт прокси `POST /v1/audio/tts` принимает
`chat_session_id` + `message_index` и озвучивает сообщение из СВОЕЙ истории
по номеру. Поля `input`/`text` нет и не будет (ограничение DeepSeek TTS API).

Поэтому плагин сначала **ищет, какому ответу соответствует присланный текст**,
и только потом делает запрос. Не нашёл — молчит с ошибкой.

---

## 1. Предусловия (проверить ДО установки)

```bash
# 1.1 Hermes установлен и профиль существует
hermes --version
echo "$HERMES_PROFILE"    # либо найти профиль вручную

# 1.2 Прокси жив и отвечает
curl -s http://127.0.0.1:18632/health
# ожидается: {"status":"ok", ...,"port":18632}

# 1.3 Эндпоинт TTS на месте
curl -s http://127.0.0.1:18632/v1/audio/voices
# ожидается список голосов: mira, echo, stella, tide

# 1.4 Плагины в Hermes поддерживаются
hermes plugins --help
```

Если `/health` не отвечает — **остановись** и сообщи: прокси не запущен,
плагин ставить бессмысленно. Не поднимай прокси сам, если не просили.

## 2. Установка

### 2.1 Найти каталог профиля

| ОС | Путь |
|---|---|
| Linux | `~/.local/share/hermes/profiles/<ПРОФИЛЬ>` |
| macOS | `~/Library/Application Support/hermes/profiles/<ПРОФИЛЬ>` |
| Windows | `C:\Users\<user>\AppData\Local\hermes\profiles\<ПРОФИЛЬ>` |

Профиль — из `$HERMES_PROFILE` или спроси у пользователя, если их несколько.
**Не угадывай профиль**: плагин в чужом профиле не загрузится.

### 2.2 Скопировать файлы

```bash
PROFILE=<путь к профилю>

mkdir -p "$PROFILE/plugins/deepseek-session-tts"
cp deepseek-session-tts/__init__.py "$PROFILE/plugins/deepseek-session-tts/"
cp deepseek-session-tts/plugin.yaml "$PROFILE/plugins/deepseek-session-tts/"

# скилл (рекомендуется: содержит разбор границ прокси)
mkdir -p "$PROFILE/skills/local-llm-proxy/references"
cp skills/local-llm-proxy/SKILL.md "$PROFILE/skills/local-llm-proxy/"
cp skills/local-llm-proxy/references/*.md "$PROFILE/skills/local-llm-proxy/references/"
```

### 2.3 ОБЯЗАТЕЛЬНЫЙ конфиг

```bash
hermes config set tts.deepseek-session.max_text_length 1000000
```

**Без этого шага озвучка сломана.** Hermes режет текст на чанки по
`tts.<provider>.max_text_length`; для незнакомого провайдера берётся
`FALLBACK_MAX_TEXT_LENGTH = 4000`. Плагин текст игнорирует, поэтому N чанков
дают N запросов и **один и тот же ответ, озвученный N раз подряд**.

CLI напечатает `not a recognized config key` — **это нормально**, ключ
читается динамически. Не пытайся «починить» предупреждение.

### 2.4 Перезапуск

```bash
# перезапусти Hermes так, как это принято у пользователя
```

Перезапуск **обязателен**: реестр плагинов и `_CONFIG_CACHE` строятся при
старте. Правка `__init__.py` в живом процессе не подхватится.

## 3. Проверка установки

```bash
# 3.1 провайдер виден
hermes tts providers
# в списке должен быть deepseek-session

# 3.2 плагин загрузился (в логе профиля)
grep -i "deepseek" "$PROFILE/logs/agent.log" | tail -20
```

Признак успешной загрузки — запись вида:

```
deepseek-session: в памяти новая сессия '<id>' (всего N): [...]
```

Она появляется при первом ходе после старта, когда срабатывает middleware
`llm_request`.

### 3.3 Сквозная проверка озвучки

1. Включи озвучку: `/voice tts`.
2. Отправь любое сообщение, получи ответ.
3. Проверь лог:

```bash
grep -E "Generating speech|deepseek-session: сессия|TTS audio saved" "$PROFILE/logs/agent.log" | tail -10
```

Ожидаемая последовательность:

```
Generating speech with plugin TTS provider 'deepseek-session'...
deepseek-session: сессия <id>, message_index=<N>, assistant: в списке X, в истории Y
TTS audio saved: .../tts_<ts>.ogg (NNN,NNN bytes, provider: deepseek-session)
```

Файл должен быть **непустой** и иметь заголовок `OggS` (Ogg Opus).

## 4. Если что-то не работает

Разбор построчный — `docs/TROUBLESHOOTING.md`. Быстрая карта:

| Симптом в логе | Причина | Что делать |
|---|---|---|
| `split into N chunks` + файлы `.chunkNNN.ogg` одного размера | не задан `max_text_length` | §2.3, затем перезапуск |
| `текст не совпал ни с одним ответом ассистента` | текст не найден ни в одной сессии | см. §5, обычно это не баг |
| `список сообщений ещё не захвачен` | middleware не срабатывал ни разу | отправь сообщение, чтобы прошёл ход |
| `прокси недоступен` | прокси не слушает порт | проверь `curl /health` |
| `прокси ответил 503: message_pending` | ответ ещё генерируется | плагин ждёт сам до `pending_wait` с |
| `прокси ответил 400: message_not_voiceable` | сессия не в истории прокси | см. §5 |
| `voice_unsupported_language` | голос не подходит языку текста | смени `voice` |
| ничего в логе вообще | запрос не отправлялся | см. §5 «ошибка в UI ≠ ошибка в логе» |

## 5. Важные ловушки (НЕ баги плагина)

Их важно знать, чтобы не «чинить» работающее.

### 5.1 Кросс-сессионный дефект

При **переключении между сессиями** может озвучиться последнее сообщение
**уходящей** сессии, а ошибка отобразится у сообщения в новой. Причина — в
ядре Hermes: `use-auto-speak-replies.ts` перезаряжается раньше, чем
`$messages` заменяется на новую сессию. Плагин тут ни при чём.
**Правки ядра не применять** — пользователь этого не принимает.

### 5.2 Склейка ответов

При переключении сессий desktop может отправить на озвучку **несколько
ответов встык без разделителя**. Такого текста нет ни в одном снапшоте как
единого сообщения, поэтому поиск промахивается всегда.
Признак: `len` запрошенного текста 7–8 тыс. символов против 0.5–2 тыс. у
обычного ответа.

### 5.3 «Ошибка в UI ≠ ошибка в логе»

Если у сообщения видна ошибка озвучки, а в `agent.log` в его временном окне
нет ни `Generating speech`, ни `ПРОМАХ` — **запрос не отправляли**. Проверь:

```bash
# время записи сообщения в базе
sqlite3 "$PROFILE/state.db" "SELECT timestamp FROM messages WHERE ..."
# ближайший конец хода
grep "Turn ended" "$PROFILE/logs/agent.log" | tail
```

Если между записью сообщения и перезапуском процесса нет `Generating speech`,
запроса не было. Ошибка в UI принадлежит другому сообщению (§5.1).

### 5.4 `text_to_speech` внутри хода

Инструмент `text_to_speech` передаёт произвольный `text`, который **не
является ответом ассистента**. Искать его в истории негде → ошибка. Это
отдельный сценарий, а не дефект поиска.

### 5.5 `/voice tts` не работает для этого провайдера

`tts_t00l_speaker` режет ответ по предложениям, а фрагмент никогда не равен
целому сообщению. Плагины в реестр стримеров `tts_streaming._REGISTRY` не
попадают. Ожидаемое поведение: озвучка по кнопке работает, потоковая — нет.

## 6. Правила безопасности

* **Не трогай ядро Hermes.** Интеграция живёт на стороне плагина и конфига.
* **Не правь прокси**, если не просили: это чужой сервис.
* **Не запускай фоновые процессы** по своей инициативе — сообщи команду.
* **Не перезапускай Hermes сам**, если это сессия, в которой ты работаешь:
  перезапуск убьёт тебя же. Попроси пользователя.
* API-ключи в отчёты не выводить.

---

## 7. Откат

```bash
rm -rf "$PROFILE/plugins/deepseek-session-tts"
hermes config unset tts.deepseek-session.max_text_length
# перезапустить Hermes
```

Плагин ничего не пишет за пределы своего каталога, кроме файла диагностики
`$TMPDIR/deepseek_tts_debug.json` (только при ошибке прокси).
