# TTS-эндпоинты локального прокси

Озвучка идёт через DeepSeek TTS API, который умеет синтезировать ТОЛЬКО свои
сгенерированные ответы. Отсюда нестандартный контракт: вход — не текст, а адрес
сообщения в истории прокси.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/audio/tts` | синтез в аудиопоток |
| GET | `/v1/audio/voices` | каталог голосов |

Стандартного `POST /v1/audio/speech` (OpenAI-совместимого) здесь НЕТ и не планируется
принципиально. Не предлагать его как решение.

## Тело запроса `/v1/audio/tts`

```json
{
  "chat_session_id": "<из completion-ответа>",
  "messages": [{"role": "user", "content": "..."}, ...],
  "message_index": -1,
  "message_id": 12345,
  "voice": "mira"
}
```

`chat_session_id` и `messages` — **альтернативы**, достаточно одного. `required: []`.

| Поле | Смысл |
|---|---|
| `chat_session_id` | id сессии DeepSeek, выданный прокси |
| `messages` | список сообщений в формате chat/completions |
| `message_index` | 0-based номер ассистентского ответа; отрицательный — с конца; опущен — последний |
| `message_id` | advanced: прямой id ответа внутри DeepSeek (принимает и строку цифр) |
| `voice` | голос из `GET /v1/audio/voices` |

Ответ — сырой аудиопоток (Ogg Opus, magic `OggS`). Ошибки — JSON.

## Как получить chat_session_id

- **non-stream**: поле `chat_session_id` в JSON-теле ответа `chat/completions`;
  официальный openai-SDK сохраняет его в `resp.model_extra['chat_session_id']`.
- **stream**: только заголовком `X-Chat-Session-Id` у SSE-ответа. В чанках поля НЕТ.
  openai-SDK при обычном `create(stream=True)` заголовки теряет — достать можно
  только через `with_raw_response`.

Два свойства, определяющие все архитектурные решения:

1. **id стабилен внутри диалога.** Продолжение истории тем же списком `messages`
   возвращает тот же id; новый независимый диалог — новый id.
2. **Клиентский id не принимается.** Если передать свой `chat_session_id` в теле или
   `X-Chat-Session-Id` в заголовке — прокси молча проигнорирует и вернёт свой.

## Дерайв сессии по `messages`

Сессия восстанавливается по истории. Проверенные границы:

- Список должен начинаться **тем же `system`**, что был в чате. Без `system` или с
  другим — `400 message_not_voiceable`. Это согласуется с инвариантом Hermes
  (system-промпт байт-стабилен на всю сессию), но означает: правка системного
  промпта разрывает связь с прошлыми ответами.
- Список, оканчивающийся на `assistant` или `tool`, находит сессию; озвучивается
  ответ на последний prompt.
- Промежуточные ответы с `tool_calls` (пустой `content`) не ломают поиск.
- Наличие `tool`-результатов в истории не мешает.

### Нумерация — проверено

`message_index` — 0-based по ассистентским ответам; отрицательные с конца; без
индекса — последний. Подтверждено распознаванием речи на нескольких сессиях:
`0` даёт первый ответ, `-1` и «без индекса» — последний, `-2` — предпоследний.

### Открытая граница: пустой `tool_call` как последний ответ

Если свежайший ассистентский ответ — вызов инструмента с `content: ''`, то запрос
без индекса и с `-1` может вернуть `502 {"error":"tts_failed","message":"DeepSeek TTS
error: no_content"}`. Если сессия нужна стабильно — передавать `message_index` явно
на текстовый ответ. При очередной проверке: смотреть, пропускает ли прокси пустые
ответы при выборе «самого свежего».

## Коды ошибок

| Код | `error` | Когда |
|---|---|---|
| 400 | `invalid_chat_session_id` | нет ни `chat_session_id`, ни `messages` |
| 400 | `invalid_message_index` | индекс вне диапазона (сообщает число ответов) |
| 400 | `invalid_voice` | голоса нет в каталоге |
| 400 | `message_not_voiceable` | сессия по этим `messages` не найдена |
| 502 | `tts_failed` | ошибка DeepSeek; текст причины в `message`, напр. `voice_unsupported_language`, `no_content` |

## Голоса

`GET /v1/audio/voices` → `{object, default_voice_id, current_voice_id, data: [...]}`.
Поля голоса: `voice_id, name, gender, languages, is_default, description`.

Наборы языков различаются: часть голосов покрывает ~29 языков (включая `ru`),
часть — только азиатские. **Несовместимый язык не отбивается валидацией**: запрос
уходит в DeepSeek и возвращает `502` с `voice_unsupported_language` в тексте.
`current_voice_id` отражает состояние аккаунта DeepSeek и на синтез с явным
`voice` не влияет — но полезен как индикатор.

## Проверка аудио

- Контейнер: Ogg Opus, проверять по magic `OggS`, а не по расширению.
- **Что именно озвучено** — распознаванием речи, не размером файла. В venv Hermes
  есть `faster_whisper`: `WhisperModel("tiny", device="cpu", compute_type="int8")`,
  конвертация через ffmpeg в 16 кГц моно, `transcribe(wav, language="ru")`.
- **Не запускать параллельные прогоны, пишущие в один каталог.** Два скрипта
  одновременно перезапишут файлы друг друга, и сопоставление «запрос → результат»
  станет недостоверным. Это уже приводило к ложному выводу о «плавающей» нумерации.
- Спектральные метрики (медиана формант по фразе) на длинных фразах НЕ работают:
  усреднение по всем гласным размывает признак. Применять только к изолированным
  словам. Для целых фраз решающий аргумент — слух пользователя.
